# 知识系统升级方案：结构化拆解 + 向量建模 + 共现矩阵联想

> 状态：设计方案（待确认后实施）。目标：让拆书知识"自动分类成导语/起承转合等叙事结构 → 向量化建模 → 写作时按叙事位置定向联想补全"，核心联想机制参考 VCPToolBox 浪潮语义动力学的共现矩阵算法，并融合 HippoRAG/GraphRAG 等开源项目的成熟思路。

## 一、现状与差距

| 已有 | 不足 |
|---|---|
| 拆书 `decon_section`（目标/钩子/冲突/爽虐/技法/引语） | **没有叙事结构标注**——不知道一段是"起"还是"转"，导语没有功能分类 |
| 素材库 13 类 + 自动标签 + 质检分级 | 标签只做检索过滤，**标签之间的关联没有建模** |
| RAG（BM25 词法倒排） | 纯词法匹配，"公证反击"查不到"进货单取证"这类语义同构情节 |
| `memory.py` 标签河道一跳联想 | 只有一跳、权重是裸共现次数、不持久化、不预计算 |
| `qwen3.5-embedding`（1024 维，53ms/条） | **完全没有用起来** |

## 三、总体架构（四层）

```
拆书/沉淀 ──▶ ①结构拆解层（自动分类 arc/lead_pattern）
                └─▶ ②向量层（知识单元 + embedding 索引）
                        └─▶ ③共现关联层（PPMI 矩阵 + 扩散激活，离线预计算）
                                └─▶ ④引力检索层（BM25 + 向量 + 共现扩散 三路融合）
                                        └─▶ 写作各阶段定向注入 ──反馈──▶ 热值强化/沉降
```

### ① 结构拆解层：自动分类起承转合与导语

拆书时 LLM 在现有字段基础上**新增三个结构字段**：

```json
{
  "arc": "转",                      // 起/承/转/合——该片段在全书弧线中的位置
  "arc_role": "最大反转+情绪顶点",    // 弧内功能（转：反转/揭底；起：炸裂开局；承：叠加施压；合：收束现世报）
  "lead_pattern": null,             // 仅开头片段有：数字悬念/身份反差/偷听反差/倒计时/伪日常裂缝
  ...现有字段（goal/hook/conflict/shuang/nve/technique/quote）
}
```

- **LLM 标注**为主：`decon_section` prompt 升级，把全书分段的相对位置（第 k/n 段）传给模型，让它结合内容判定 arc；`decon_book` 升级输出全书 `arc_map`（四段边界、卡点密度曲线、虐爽情绪序列）。
- **规则兜底**：LLM 判定缺失时按位置比例兜底（0-20% 起 / 20-55% 承 / 55-85% 转 / 85-100% 合），保证每条知识都有结构标注。
- **导语库**：成稿沉淀与拆书开头自动归入导语库并打 lead_pattern 标签，供导语阶段对照。

### ② 向量层：知识单元 + 向量索引

**知识单元（Unit）**是统一的最小知识粒度（一条导语/一个情节片段/一个反转设计/一条技法/一句金句）：

```json
{
  "id": "U20260921_001", "kind": "arc_segment",   // arc_segment/lead/hook/reversal/technique/quote
  "arc": "转", "arc_role": "最大反转",
  "direction": "婆媳大战", "emotion": "怒→爽",
  "text": "儿媳在装修漏洞里发现购房合同更名费一千八，当场识破婆婆偷名……",
  "tags": ["装修漏洞", "识破", "房本"],
  "source": "拆书:锁金宫", "quality": "high", "heat": 0,
  "embed_dim": 512
}
```

- **向量化**：`qwen3.5-embedding` 走 `/api/embed`，文本模板 `"[{direction}|{arc}|{emotion}] {text}"`（把结构信息编进向量文本，同弧位的情节在向量空间天然聚拢）；**MRL 裁剪到 512 维**（省一半内存、余弦更快）。
- **存储（零依赖）**：`workspace/kb/units.jsonl`（元数据）+ `workspace/kb/vectors.npy`（float32 矩阵，1 万条 × 512 维 ≈ 20MB）+ id 偏移表。查询 = numpy 暴力余弦（1 万条 <10ms）。规模超 5 万条再引入 usearch/hnswlib（接口预留）。
- **增量写入**：拆书/成稿沉淀/素材 deposit 时逐条编码入索引；全量重建命令 `kb rebuild`。

### ③ 共现关联层：PPMI 共现矩阵 + 扩散激活（VCP 河道升级）

- **共现对象**：知识单元的 tags ∪ arc ∪ emotion ∪ direction，全部视为"河道节点"。
- **离线预计算**：`workspace/kb/cocomatrix.json` 存 tag-tag 稀疏矩阵。权重用 **PPMI** 而非裸共现次数（认知科学结论：扩散激活的联想强度就是 PMI）：

  `W(x,y) = max(0, log [ p(x,y) / (p(x)·p(y)) ])`

  两个冷门标签的强共现会得到高权重，两个高频标签的平凡共现权重趋零——这正是 VCP "虫洞跃迁"想要的"高质量弱关联"效果。
- **在线查表**（VCP 原则：重计算离线完成，在线只查表）：入库/整理完成后自动重建矩阵（增量累加，毫秒级）。
- **扩散激活**：检索时以种子单元的 tags 为初始激活，沿矩阵扩散：

  `act(v) = Σ W(u,v) · act(u) · damp^hop`，钟型阻尼 `damp=0.5`，扩散 2 跳后截断，取激活值 top-m 的标签回查单元库。
  效果示例：查"婆婆藏赔偿款"→ 河道扩散激活"公证/进货单/取证/当票"等**从未字面匹配过**的关联单元。

### ④ 引力检索层：三路融合 + 叙事位置定向

- **三路召回**：BM25（现有 rag.py）+ 向量 KNN（新）+ 共现扩散（新），用 **RRF（Reciprocal Rank Fusion，k=60）**融合排序——三路各出 top-20，按 `Σ 1/(60+rank)` 合分。
- **叙事位置定向加权**：写作时已知当前章节的弧位（大纲 5-6 章 → 01-01 起 / 02-03 承 / 04-05 转 / 末章合），对应单元类型加权：写"转"章时 `reversal ×1.5`、`hook ×1.2`；写"合"章时 `technique(收束) ×1.5`。
- **分视图注入**（写什么查什么）：
  | 阶段 | 视图 | 检索内容 |
  |---|---|---|
  | 提梗/大纲 | 结构骨架视图 | 同方向高分 `arc_map` 对照（借结构，禁抄情节——与现有查重联动）|
  | 导语 | 导语库视图 | 同方向高分 lead_pattern 导语（含六句框架标注）|
  | 逐章 draft | 弧位视图 | 当前 arc 的情节单元 + 技法 + 金句（现有 memory.recall 升级为 kb.recall）|
  | 润色 | 技法视图 | 卡点密度/语言红线同类技法 |
- **反馈回路**（Graphiti 时序思想）：命中即强化（现有 `touch`），发布数据差的关联知识降权，长期零复用沉降——与记忆库冷热分层共用一套机制。

## 五、实施计划（四阶段）

| 阶段 | 内容 | 预估 |
|---|---|---|
| P1 结构+向量 | decon 两级 prompt 升级（arc/arc_role/lead_pattern/arc_map）；`studio/kb.py`：Unit 库、向量索引、增量/重建；拆书与 deposit 接入 | 2 天 |
| P2 共现+融合 | PPMI 矩阵预计算；扩散激活；三路 RRF 融合的 `kb.recall` | 1-2 天 |
| P3 写作接入+面板 | stage_outline/lead/_chapter_ctx 三处注入改造；看板素材库页签加"结构视图/联想测试"面板；`kb` CLI（stats/recall/rebuild） | 1-2 天 |
| P4 可选增强 | Personalized PageRank 多跳（HippoRAG 式）；发布数据反馈降权；同方向结构模式摘要（GraphRAG 式社区摘要） | 按需 |

## 六、验收标准

1. 拆书入库后 100% 单元带 arc 标注，人工抽查分类准确率 ≥85%；
2. 1 万知识单元下向量查询 <100ms，共现矩阵重建 <5s；
3. 联想案例可复现：查"婆婆藏赔偿款"能召回"公证/进货单取证"等零字面重叠的关联单元；
4. 注入预算可控（逐章检索注入 ≤600 字，不挤占正文上下文）；
5. A/B 一篇：接入知识系统后的成稿读者团均分不低于基线（7.5），卡点密度门禁通过率不降。

## 七、风险与对策

| 风险 | 对策 |
|---|---|
| GLM 类模型拆解输出结构不稳 | 拆解标注用 27B/4B（纪律好），已有多层 JSON 防御 |
| 全量首次向量化耗时（1 万条 ≈ 9 分钟） | 增量编码 + 后台线程 + 断点续跑 |
| 向量检索误召回挤压正文上下文 | 注入字数硬预算 + 三路融合的多样性去重 |
| 素材存量迁移质量 | 迁移脚本 dry-run 模式，人工抽检后再生效 |
