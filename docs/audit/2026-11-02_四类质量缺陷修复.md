## 二、判据：从「猜」退到「只判能精确判的」

### 走过的弯路（都记在册，避免重犯）
1. **v1 动词前 2–3 字猜人名** → 30+ 个假名字：则阴狠 / 翠堆砌 / 监尖细 / 立刻捧 / 将碗递。
2. **v2 角色词 + 2 字** → 仍误报：尖细 / 惊呼 / 匆匆 / 刻薄 / 领路 / 名叫 / 总管 / 统领；
   `unknown` 层被 手中 / 死死 / 浑身 / 脸色 污染。
3. **`「她」人称漂移`判据** → 9 节误报 5 节（太后、阿蛮、前两位妃子本来就用「她」）。
4. **`end_hook` 关键词重叠判线索断头** → 9 个交界报 5 个假阳性，全是同义改写。
5. **`_n_gram_hit(carry_out, next, 4)`** → 报 5 个断头，全是假阳性（中文短语中心语在尾部）。
6. **句级 bigram Jaccard 判「重演上一节」** → 「碗沿贴上嘴唇」与「碗沿磕在唇齿间」只共享「碗沿」。

### 最终落地的判据（`studio/continuity.py`）
- `cast_coverage` / `cast_gaps`：只查**计划声明过**的 major 角色；`pov=True` 整条跳过
  （第一人称主角通篇写「我」，名字不落地，拿名字查必误判）；非 major 配角未退场不报。
- `carry_hit`：从交接短语**尾部**往前找最长可命中片段，≥3 字算接住，2 字仅当不是泛词
  （名字/东西/事情/消息…）才算。
- `dup_across`：包 `langqa.cross_dup`，逐节累加前文，阈值 14 字。
- `pov_breaks`：抠掉引号后逐句找主角名 —— 叙述里出现主角名字即断裂。
- `tail_repeat`：节尾段与本节前文的最长公共子串 ≥12 字即判复述。
- `fix_pov`：引号外把主角名换回「我」（纯词法错误，可精确修，引号内不动）。

真实稿验证：`pov_breaks`/`tail_repeat` 把终审判官报的 3 处 high 硬伤 **3/3 全抓到、零误报**。

## 三、契约补进计划与写作提示词

- `prompts/section_plan.md`：输出 JSON 增 `characters[{name,role,major,pov}]`（3–6 人，
  名字定死不许改）与每节 `cast` / `carry_out` / `words`；字数参数化 `{{SEC_LO}}-{{SEC_HI}}`。
- `prompts/write_section.md`：
  - 铁律 11 人称绝不跳（主角名只许出现在「」内）；
  - 铁律 12 节尾不许总结、不许复述；
  - `{{CAST}}` 人物名册、`{{CARRY_IN}}`/`{{CARRY_OUT}}` 交接项、`{{FACTS}}` 硬事实台账；
  - `{{PREV_TAIL}}` 由「上一节末 300 字」改为**上一节全文**（800–1100 字 ≈ 600–700 token），
    并声明为「硬设定，只许沿用不许改写」。
- `studio/pipeline.py`：
  - 每节目标字数取 `section.words`，门禁区间 ±25%（原先一刀切 600–1000，计划里的 `words` 没人读）；
  - 节级新增：人称断裂、节尾复述（每轮都判）、衔接重演（每轮都判）、跨节重复就地改写；
  - 每节定稿后抽「硬事实」并**逐字校验**（`quote in text`，编造的丢弃），累计注入下一节。

## 四、另外三项

- **导语字数**：300–400 → `cfg["lead"]["words"]`（默认 150–220）。此前五套口径各写各的
  （lead.md / `_det_check` / `stage_lead` 扩写 / `_STAGE_CRITERIA` / market_guide），
  改一处不改五处，模型永远被两边拉扯。新增 `_stage_criteria(stage, cfg)` 现算。
- **书名**：`_CONFLICT` 补古言/宫廷动作（赐/赏/灌/灌药/废/打入冷宫/验身…），新增「前例钩」
  `_OMEN`（前两个…都没活过/上一个/前一位，+2）。标定后真实书名分：
  太后赐药前两个都没活过三年 **10**（原 5）、婚房让给弟弟 7、拆迁款 7、主播翻车 7、
  港岛73 5、文艺名（萤火之城/娇养玫瑰/心肝宠/够野）**0**。
  `_pick_title` 改为取**卖点分最高**的合格项；`stage_pitch` 重试 3 次、≥7 才收。
- **逻辑不通顺**：靠两道联网判据压 ——
  ① 硬事实台账（防「药是安神汤还是断肠草」「停灵几天」自相矛盾）；
  ② 衔接重演检测 `_sec_replay`（轻模型判「这一节开头是否重演上一节」，
  判到了给出「应该从哪一刻写起」的具体提示）。

## 五、效果（确定性指标，不受判官波动影响）

同一题材连跑三版成稿，用 `_sec_replay` 重判全部节间边界：

| 版本 | 判据状态 | 重演边界数 | 字数 |
|---|---|---|---|
| v7 | 无重演判据 | **3** | 9430 |
| v9 | 只有硬事实台账 | 1 | 9398 |
| v10 | 硬事实 + 重演检测 | **0** | 9987 |

终审分：v7 66 / v8 68 / v9 68 / v10 63 —— **run 间波动 ±6 分，大于单次改动的增益**，
所以本轮的验收不拿单次分数说话，拿确定性缺陷数说话。v10 交付等级 B 可投（有瑕疵）。

## 六、仍然没解决的（诚实清单）

1. **终审 72 分门槛未过**（稳定在 62–68）。主因是写作模型的习惯，不是流水线：
   「嘴角勾起一抹」「眼底闪过一丝」「就在这时」在整稿去味后仍会复现；
   数字堆砌（三钱乌头、二两断肠草）、总结升华段、现代词（绞肉机）同理。
2. **AI 口癖的收敛依赖整稿 `_ai_deflavor`**：节级只给一次修正机会，
   实测三轮盲改压不住，所以最后一轮改为「语言病放行、结构问题照拦」。
3. **判官本身有误判**：v8 r01 把「01 结尾碗贴嘴唇 → 02 开头碗磕牙齿」判成重演，
   实际是正常承接。重演检测在 README 里明确写了「停在半途、顺势写完不算重演」，
   但判官不认这条口径 —— 两边口径需要对齐（下一步）。
4. **微调 35B 不可行**（16GB 显存 vs 69.3GB 权重、块扩散训练目标不在任何现成框架里），
   已在 `2026-11-01_Clover作写手实测.md` 里结论归档。
