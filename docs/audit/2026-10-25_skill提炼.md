## 0. 结论摘要（Top 10）

1. **短篇项目当前最大的问题不是"缺规则"，而是"同一规则有多份副本且阈值互相打架"**：`data/lang_rules.json`、`prompts/draft.md`、`prompts/review.md`、`data/style_guide.md` 四处各写一份硬禁词/限量表，已造成 2026-10-18 报告第 14/15/17 条那类"门禁误伤→打满放行"与"变体漏检"。
2. **可复用的最高价值不是哪条词表，而是"规则治理机制"**：C2 `tools/check-conflicts.py` 的"唯一权威源 + 阈值冲突守卫 + 越界检测"、C1 `doc-budget.json` 的"热路径字数预算"、D 的"判据抽象层红线 + 状态语义 + 继承复用"，能直接治本。
3. **去 AI 味必须升级为三层（表达/用笔/故事），并显式规定"润色不得改剧情"**——C1 `story-logic.md:32-41` 的授权边界表，正好对应历史缺陷 18/19「终审越修越短」「润色把扩写成果吃回去」。
4. **情绪直写是合法的**（C1 `expression.md:40-52`、C1 `short-craft.md:23-42`），现有 `lang_rules.json`「很+情绪词」与「情绪直白」规则需要收窄而不是删除，否则等于和下沉市场文风正面冲突。
5. **伏笔有 prompt 要求（`P/prompts/outline.md:52` 要求伏笔≥2 条并标注埋设/回收章）但没有数据载体与回收校验**——这是"零成本确定性检查"最容易补的一大块：`data/foreshadow.json` + `studio/continuity.py`。
6. **对话有大量可抄的操作级模板**（C1 `dialogue-mastery.md` 的压制/反转/心死三模式、议程与潜台词、七维人物差异），且能大幅减少 LLM 门禁的 token 消耗（写前约束强于写后打回）。
7. **`review.md` 的"命中即打回"清单需要改成"引用规则编号"**，否则每加一条规则就要改 3 个文件，且必然漂移（C2 `short-craft-prompt.md:54` 的"同一语义只出现一次"是硬门禁）。
8. **项目开发流程可以立刻落地 6 个守卫**（规则漂移、占位符契约、prompt 预算、回归串、具体字数、门禁输出规范），全部纯 stdlib、零 token、退出码语义统一。
9. **D 的 DoG 不适合直接进流水线**（它要求常驻会话 + agentic 子代理），但**适合做"发布前的人工/agent 复核清单"**：把"这篇成稿好不好"拆成可逐项判定的树，与我们已有的确定性门禁分工明确（D 铁律：任何分支不能全程序化）。
10. **本项目应明确"不引入"清单**：OpenWrite 的 `novel_*` 工具类技能（canon/learn/write-next/review-chapter/revise-span/progress/export-book/dog-*-query）依赖 bridge 运行时，本项目一律只取原则不取实现。

## 3. 写作技法可落地清单（16 条）

> 每条结构：**规则本身 → 来源 → 落地位置 → 可直接抄的草案**。
> 优先选"能变成结构化模板/确定性检查/提示词硬约束"的规则，不选空泛原则。

### W1 对话三功能门槛 + 情绪承接（每句台词都要有用）

- **来源**：`C1/skills/story-short-write/references/dialogue-mastery.md:30-38`（对话核心规则）、`:38`（情绪承接）；`A/dialoguequality/SKILL.md:69-99`（解释性/过度礼貌/完美逻辑/套路表达）。
- **规则**：一段对话至少承载"推进剧情 / 增加期待 / 展示人设"之一，都不承载就删或用叙述带过；情绪场景里**每句还要回应上一句的情绪状态（承接/偏转/升级/退缩）**；连续多轮"只交换信息、句间无情绪承接"= 机械对话。
- **落地**：`P/prompts/draft.md` 对话硬规则（现有 `:8-14`）+ `lang_rules.json` 新增一个**低误伤**结构检查：连续 N 轮对话（`「」` 行）之间无动作/环境/心理行 → 提示（`low`，不阻断）。
- **草案（可直接进 draft.md）**：
  > 每段对话必过三问：①这轮对话让剧情/信息/关系变了什么？②对方的情绪被接住了还是被无视了？③遮住人名，能不能分出谁在说？
  > 连续 4 轮以上纯对话（没有任何动作、环境、心理、停顿）即为"话剧腔"，必须插入一个动作或换场。
  > 禁止：A 向 B 解释 B 已知的事；所有人说话都完整、礼貌、有问必答；用"受教了/所言极是/你说得对"当回应。

### W16 删除/压缩/展开三测试（治"扩写注水"与"越修越干"）

- **来源**：`C1/skills/story-review/references/narrative-focus.md:21-29`（删除测试/压缩测试/展开测试）、`:31-38`（细节要服务这场戏：动作/心理/对话/环境/群像）、`:19`（"平"可能来自重心写薄，也可能来自故事没有变化，先判断是哪种）。
- **规则**：
  - **删除测试**：删后是否损失事实/伏笔/因果/空间/声口/关系/情绪持续时间？
  - **压缩测试**：用一句概述替代后，读者是否只剩结果、无法体会过程？
  - **展开测试**：新增每一轮是否使信息/处境/判断/关系/感受发生变化？只换措辞强调强度 = 应收回。
- **落地**：`P/prompts/polish_fix.md` 与 `expand.md` 直接引入三测试；`P/prompts/draft.md` 的"写前必读"加一句"扩写时只补原计划漏掉的动作/证据/选择/后果，不得加卡点/对话/回忆/环境凑长度"（C1 `story-short-write/SKILL.md:99` 已有同义句，可直接抄）。**这条同时是历史缺陷 16/19 的根因**：字数震荡源于"只扩不改"没有边界。
- **草案**：
  > 扩写只做三件事：①把已定但没写出的动作写出来；②把结论改成交锋过程；③把概述改成一次选择。**禁止**为凑字数新增：新人物、新对话轮次、回忆段、环境描写、旁人反应。
  > 压缩只做三件事：①删不改变判断的复述；②合并同一动作的碎句；③把解释改成动作。**禁止**删掉伏笔、因果承接、情绪峰值。

### 4.2 合并策略（原则 + 具体动作）

**原则一：一个对象只能有一个 owner 文件。** 其余位置引用编号，不复制内容。

| 层 | 唯一 owner | 内容 | 其他位置怎么写 |
|---|---|---|---|
| L1 平台/结构参数 | `data/platforms.json` + `config.yaml` | 字数区间、每节字数、卡点密度、人称、平台格式 | prompt 里只写 `{{PLATFORM_SPEC}}`，由 `pipeline.load_platform` 注入 |
| L2 语言规则 | `data/lang_rules.json` | 词表、正则、阈值、severity、suggest | prompt 里只写"见规则库 R-xx"，由 `prompts.py` 注入摘要 |
| L3 判据/举证 | `prompts/review.md` | 六维/结构三问/逻辑官/举证格式 | 不再写具体词表，改引用 L2 的 `label` |
| L4 写作技法 | `prompts/draft.md` + `data/style_guide.md` | 节奏/详略/情绪落点/对话模板 | 不写禁用词数量线（那是 L2） |
| L5 连续性真源 | `prompts/bible.md` + 项目 `state.json`/`foreshadow.json` | 人物/关系/伏笔/状态 | `memory.py` 只存"作者偏好"，不存设定；`canon/learn/world-query` 的单一真源原则照此执行 |

**原则二：严重度只由 L2 定义。** `review.md` 的"命中即打回"必须等价于 `severity: high`。现状 K3/K8 违反，需一次性对齐（"静了两秒"统一 high；"很+情绪词"统一 mid 且收窄）。

**原则三：阈值统一按"节"计，全篇只在交付门用总量。** 本项目章节 800–1200 字、全篇 7–8 节，`langqa` 的 `_freq_limits` 已按字数折算（`studio/langqa.py:75-85`），因此**以 langqa 的节级口径为准**，`review.md` 的"全篇≥N 次"全部改写为"每节 ≥N/节数"或直接引用 R-xx。

**原则四：冲突裁定表内联到提示词。** 抄 `C2/skills/prompt-crafting.md:36-45` 的 hierarchy，落成 `P/prompts/_adjudication.md`（只被 system 段引用，不产生 token 浪费的重复）：

> 冲突时高优先级不让步；**写作侧只执行不裁定**（不自行判断"这条规则可以破例"）。
