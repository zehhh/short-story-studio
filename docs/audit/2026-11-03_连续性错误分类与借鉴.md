# 连续性错误分类：文献调研与借鉴落地

日期：2026-11-03
起因：用户「继续，先针对目前存在的问题进行搜索研究，看看有没有论文、文献、开源项目已经能解决这个问题，然后再进行调试修改」。

要解决的问题是 v11 真跑后终审仍报的 4 处 high 硬伤，归纳起来是三类：

1. **时间线倒退**：小节 03 结尾人已走到门口、天刚亮，小节 04 开头又「天刚亮」，把同一个早晨重铺一遍；
2. **无因之果**：「袖中银针弹出击碎瓷壶」「运劲改脉」——前文从没交代过这个人有银针、会改脉；
3. **同一动作一节内写两遍**（「指节敲了两下」）。

## 一、最贴合的论文：ConStory-Bench

**Lost in Stories: Consistency Bugs in Long Story Generation by LLMs**（arXiv:2603.05890，Microsoft + SUTD，2026-03）。

它做的事正是我在做的：建一个长篇叙事一致性基准（2,000 prompts / 4 类任务），给出**错误分类学**，再配一条自动化检测流水线 ConStory-Checker。

### 分类学（5 大类 19 子类，原文 Table 2）

| 大类 | 子类 |
|---|---|
| Timeline & Plot Logic | Absolute Time Contradictions / Duration Contradictions / Simultaneity Contradictions / Causeless Effects / Causal Logic Violations / Abandoned Plot Elements |
| Characterization | Memory Contradictions / Knowledge Contradictions / Skill Fluctuations / Forgotten Abilities |
| World-building & Setting | Core Rules Violations / Social Norms Violations / Geographical Contradictions |
| Factual & Detail Consistency | Appearance Mismatches / Nomenclature Confusions / Quantitative Mismatches |
| Narrative & Style | Perspective Confusions / Tone Inconsistencies / Style Shifts |

**实测结论（对我们最有价值的三条）**：
- 一致性错误**最集中在 factual 与 temporal 两个维度**——正是我们剩下的两类硬伤；
- 错误**倾向出现在叙事中段**（长篇越到中间越松）；
- 错误**倾向出现在 token 级熵更高的片段**（模型自己也在犹豫的地方），且某些错误类型**成对共现**。

### 检测流水线（4 阶段，原文 §2.3）
1. **Category-Guided Extraction**：按五类分别用类目提示词扫出「易矛盾片段」；
2. **Contradiction Pairing**：片段两两比较，判 Consistent / Contradictory（沿 CheckEval 的做法）；
3. **Evidence Chains**：每条判断必须挂**原文逐字引用**作为证据；
4. **JSON Reports**。

它在自己的人工对齐测试上 F1 = 0.678（recall 0.550 / precision 0.884）；**偏向高 precision**——这一点我完全同意，见下。

## 二、更早的两篇奠基工作（思路来源）

- **Re3: Generating Longer Stories With Recursive Reprompting and Revision**（arXiv:2210.06774）——分「计划 → 逐段写 → 重提示 → 修订」四段循环，关键是**每一段都带着压缩后的剧情摘要与设定重提示**，而不是让模型一口气写完。我们的「逐节写 + PREV_TAIL 给上一节全文 + 硬事实台账」就是这条路。
- **DOC: Improving Long Story Coherence With Detailed Outline Control**（arXiv:2212.10077）——把大纲拆成「详细大纲」与「详细控制器」两层，控制器逐段检查「这一段有没有偏离详细大纲」。对应我们的「细纲必写场景 + 契约指标」思路。

这两篇的共识：**长稿的连贯性靠外部结构，不靠模型自觉**。

`QianBi-Novel` 的作者自述最能对上我们的处境：

> 写一部长篇网文真正的难点不是「让 AI 写出一章」，而是写到第 300 章时设定还没崩、代价还没赖账、伏笔还记得收。
> 我认为写作 Agent 的终局不是「更会写的模型」，而是**会拒绝的流水线**。

以及它强调的三件事——**引证验真、确定性复检、承诺对账**——和我们已经在做的（逐补丁局部体检、`_det_hits_count` 独立信号、判据清单写死豁免口径）是同一套工程判断。

## 四、采纳与不采纳

### 采纳（本次已落地）

1. **按分类学组织判据，而不是按「想到什么写什么」**。新增 `studio/state.py`，文件头直接写清每条判据对应 ConStory 的哪个子类。
2. **无因之果做确定性判定**：`state.causeless()` = 「上一节没出现过」∧「本节首次出现」∧「那句话确实在拿它做事（弹出/刺入/服下…）」∧「那句话里没有来历线索（摸出/藏/学过/母亲留…）」四项合取。
   全库 35 篇真实成稿跑下来只命中 3 处，其中 v11 那处「袖中银针弹出击碎瓷壶」是真阳性。
3. **时间线重铺改成「上下文注入 + 轻模型判」**：
   - `state.prev_time_hint()` 把「上一节最后写到的时点」直接写进提示词（`{{PREV_TIME}}`），从源头减少重铺；
   - 判定交给 `pipeline._sec_boundary`（原 `_sec_replay` 扩项），要求它带原文理由。
4. **判据清单进判官提示词**：`prompts/review.md` 新增「判据定义与豁免（硬口径）」，把重演/场景重复/节长失衡/AI 腔/升华段/逻辑矛盾六个判据的**可判条件与豁免条件**写死，并要求每条 issue 带 `location` 与可逐字回查的原文。
5. **写手侧同步两条铁律**：`prompts/write_section.md` 新增铁律 13（时间只许往前走）、14（新本事/新东西第一次露面必须交代来历）。

### 不采纳

- **ConStory-Checker 的四阶段全流程**：它的 Stage 1 是「五类各跑一遍提取」，2,000 条 prompt 级别可以，我们每篇只要 9 节、每节 1 次调用已经是成本上限。我们取它的**分类学与证据要求**，不取它的穷举策略。
- **`QianBi-Novel` 的条目化世界书**：我们已有 `bible.json` + 硬事实台账 + 世界书机制，重做等于推翻现有上下文装配基线，收益不抵风险。
- **知识图谱式人物关系推理**：见 `docs/dev/DECISIONS.md` 决策 31/35 的实测结论，中文没有词典时分不清「侍女阿蘅」和「嬷嬷立刻」，猜名字必误判。

## 五、结论

我们的判据体系与 2026 年最新的 ConStory-Bench 分类学是同构的，缺的部分（无因之果、时间重铺）这次补上了。**唯一的方法论分歧**在「时间倒退能不能确定性判」：

论文用 LLM 逐类扫；我一开始想用词表判，全库 35 篇实测误报 **47 次**（`下午 → 早上` 是在回忆那天早上、`半夜 → 夜里` 的时点词出自台词、`傍晚 → 清晨` 跨夜但没写「次日」），据此判定**中文叙事不靠时点词标记日期推进，词法比较不可用**，改为上下文注入 + 轻模型判。这条结论已写进 `studio/state.py` 顶部与决策 40。
