# Clover-35B-A3B-Preview 作写手实测（2026-11-01）

用户指令（m20739）：「写手模型更换成本地模型，更换成最近新出的 Clover-35B-A3B-Preview
扩散模型看看效果如何，直出效果如果不好，能不能尝试微调看看」

**结论先说**：直出不可用于生产（输出不稳定），本机微调也不可行（69.3GB 权重 + 自定义
扩散架构）。写手保持现有 API 模型。

## 1. 模型与环境

| 项 | 值 |
| --- | --- |
| 模型 | `Diffuspace/Clover-35B-A3B-Preview`（2026-10-24 发布，Apache-2.0） |

| 显卡 | RTX 4060 Ti 16GB（实测占用 15444/16380 MiB） |
| 卸载 | `-ngl 99 -ncmoe 16`（前 16 层 experts 留 CPU） |

## 2. 实测矩阵（同一份 28k 字真实 draft 提示词，目标 1125 字）

| 样本 | 采样 | 字数 | 碎句/千字 | 碎句链/千字 | 对白占比 | AI 味 | 判读 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| baseline-deepseek（现役 API） | t0.85 | 1128 | 0 | 0 | 0.519 | 0 | 可用 |
| clover-full | t0.85 | 1049 | **16** | **20** | 0.266 | 3 | 碎句灾难（用户抱怨的四类病全中） |

| clover-t0.7 #2 | t0.7 | 4910 | 0 | 0 | 0.866 | 1 | **台词循环退化**（同一句重复到 4096 token 上限） |

| clover-t0.7 + repeat1.2/freq0.3 | t0.7 | 696 / 260 | 0 | 0 | 0.0 / 0.109 | 4 / 1 | 格式崩塌：半角标点、无分段、跑题去写「简介/标题」 |

## 3. 三条硬结论

1. **温度窗口极窄且不可靠**。0.6 死循环、0.75 起碎句、只有 0.7 附近干净，而 0.7 两次
   采样一次干净一次循环——**约一半样本不可用**。这不是「调参能解决」的问题，是产出
   稳定性问题：生产环境一章写坏就得整章重跑，而重跑仍有约 50% 概率写坏。
2. **llama.cpp 默认 `repeat_penalty=1.0`（等于关闭）**，Clover 在无惩罚时会陷入同句循环；
   但加上 1.2 惩罚后模型反而丢掉分段与全角标点、并跑题去写「标题/简介」。惩罚参数
   在它身上是**双向有害**，没有可用的中间档。
3. 即使干净样本也有事实/格式问题：把「你小子」安在女角色曹婷婷身上（曹金凤对女儿说
   「你小子要是敢反悔」）；末尾 `[本章摘要]` 里写了正文没发生的情节（「秀兰回到城中村
   出租屋」，正文只到巷口）——摘要与正文对不上，后续章节会按错的摘要衔接；引号用「」
   而非弯引号（后者项目 `normalize_quotes` 可兜）。
   （注：`[本章摘要]` 本身是 `prompts/draft.md:170` 要求的输出格式，不是模型自造。）

## 4. 微调可行性：本机不可行

| 障碍 | 数字 |
| --- | --- |
| 全精度权重 | 69.3GB（26 个 safetensors 分片），本机 16GB 显存 + 23.5GB 内存 |
| QLoRA 4bit | 仅权重约 18–20GB > 16GB 显存，**连加载都做不到** |
| 架构支持 | `model_type=clover_moe`，仓库随附 `modeling_clover_moe.py` / `configuration_clover_moe.py` / `sampling_clover_moe.py`，需 `trust_remote_code`，**不在 transformers 主干** |
| 训练目标 | 块扩散（去噪整块），不是 causal LM 的 next-token 交叉熵——TRL/PEFT 的标准 SFT 损失与它的推理过程不一致，得自己实现扩散训练目标 |

可行但性质不同的替代：用 `dataset-forge/` 已有的数据（795 篇 onehu 短篇 / 1173 万字 +
起点短篇，SFT/CPT jsonl 齐全，已跑过 Qwen2.5-1.5B 的 lora v1–v3）微调**小稠密模型**。
这条路能落地，但小模型的文笔天花板明显低于现在的 `qwen3.8-flash` API，治不了
「35B 才有的语感」。

## 5. 建议

1. **写手不换 Clover**，继续用现役 API 写手（同一提示词下 0 碎句、0 AI 味、36s/章）。
2. 本地模型的价值在**离线/零成本**场景。若确有需要，优先试更小的稠密模型 + 现有
   `dataset-forge` 微调，而不是 35B MoE 扩散模型。
3. 如果将来硬件升级到 80GB 显存，Clover 仍要先解决「扩散训练目标」才能微调——那是
   一个模型工程问题，不是本项目该背的负担。

## 6. 复现步骤

```bash
# 1) 编译（需 CUDA Toolkit 12.6 + VS2022）
E:\build\build_clover_cuda.bat

# 2) 起服务（16GB 卡：-ncmoe 16 刚好，再少就 OOM）
llama-server.exe -m E:/models/clover/Clover-35B-A3B-Preview-Q4_K_M.gguf \
  --host 127.0.0.1 --port 8732 -ngl 99 -ncmoe 16 -c 40960 -t 8 -fa on \
  --jinja --no-reasoning-preserve

# 3) 渲染真实提示词（任一已有项目）
python clover_eval.py build "E:/小说/短篇/workspace/projects/<项目目录>" 1

# 4) 跑 + 机审
python clover_eval.py run clover-t07 --base http://127.0.0.1:8732/v1 --key local \
  --model clover --temp 0.7 --max-tokens 4096
python clover_eval.py judge clover-t07
```

**注意**：不关思考时 `completion_tokens=4096 / reasoning_tokens=4096 / 正文 0 字`
（与 deepseek-v4.1-flash 同一个坑）。本地端点必须带
`"chat_template_kwargs": {"enable_thinking": false}`，网关端点用 `reasoning_effort: "none"`。
