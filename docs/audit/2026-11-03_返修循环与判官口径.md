# 返修循环与判官口径（m24702）

用户提出的三个问题：**不限轮数（失控烧钱）、盲目修改、判官判断标准不清**。
本文记录定位、改动、以及用真跑（v11）验证的证据。

---

## 一、不限轮数

### 症状
`final_fix_rounds = -1`（配置语义为「不限」），循环 while 条件里没有任何轮数上界。
实测 v10 一轮稿子跑 7 轮终审修复，每轮 6 次判官调用（每次 2000–2500 output token），
光修复就烧掉 10 万级 token，最后仍以 `62→68→66→68` 原地打转收场。

### 改法
1. `ABS_FIX_ROUNDS = 20` 硬上界，打进 while 条件：
   ```python
   while (... and _abs_n < ABS_FIX_ROUNDS):
   ```
2. **日志必须印真实上限**。原先：
   ```python
   f"第 {rnd_f}/{'∞' if fix_rounds < 0 else fix_rounds} 轮修复"
   ```
   `fix_rounds < 0` 只是「配置没定上限」，循环其实受 `ABS_FIX_ROUNDS` 约束，
   印成「∞」会让人以为真无限。改为 `_cap_f = ABS_FIX_ROUNDS if fix_rounds < 0 else fix_rounds`。
3. 三条止损（任一命中即停）：
   - **本轮没有一处补丁通过局部体检**（`new_full == full`）——继续跑也只是白烧判官 token；
   - **连续 2 轮无任何改善**（分数不涨且确定性缺陷不降）；
   - 累计提升 < 3 分且已跑 3 轮以上（`MIN_TOTAL_GAIN`）——长时间小碎步不划算。

### v11 实测
```
58 → 62 → 66（≥65 改走定点补丁）→ 63 回滚 → 62 但确定性缺陷 10→5 保留
→ 68 → 66 回滚 → 68 回滚 → [guard] 连续2轮未提升，收敛到头，终止
```
7 轮后由守卫终止（不是 20），最终采用 best 68。**行为符合预期：有界、可解释、不再空转。**

## 二、盲目修改

### 根因
原来的补丁轮是「一把改完再整稿重判」：
模型拿到 6 条意见 → 一次性改 6 处 → 整稿重新评分 → 分数不动 → **整轮回滚**。
回滚把改好的补丁也一并扔掉，下一轮再盲改一遍。四轮下来没有任何一处改动被确认有效。

这与文献结论一致：**intrinsic self-correction（只靠模型自评自改，没有外部信号）基本无效**，
必须有 verifier 才能转正增益（arXiv:2601.00828 等对 self-correction 的分解实验均得到该结论）。
我们的 verifier 不必是模型——**确定性判据就够**。

### 改法
1. `_span_pen(cfg, text)`：一段文本的确定性缺陷分
   = langqa high/mid 命中数 × 3 + 碎句/语序/欧化病分。窗口取 ±700 字
   （覆盖一段对话或一个动作序列的语义范围，又不把全稿噪声拉进来）。
2. `_apply_patches_verified(cfg, full, patches, window=700)`：**逐条**应用补丁，
   每条只对改动处做局部体检，`after <= before` 才留下；改坏的当场丢弃并记 `reason`。
3. 接受条件增加独立信号 `_det_hits_count(cfg, text)`（langqa high/mid 命中**条数**，
   不是标签种数）。
   - 判官分没涨、但缺陷条数下降 → **保留本轮改动**，`fail_streak` 清零，继续迭代。
   - 两者都不改善 → 回滚并累计失败。

### 一个必须记住的坑
`_det_hits_count` 最初基于 `_full_ai_hits` 数标签种数，而 `_full_ai_hits` 走的是
「逐节扫描取并集」——遇到**没有节头**的片段会一节都切不出来、直接返回 `[]`。
实测「就在这时，空气凝固了，嘴角勾起一抹冷笑。」被算作 **0 条缺陷**，
于是「改坏了」和「没改」在所有窗口体检里得分相同。改为逐节 `langqa.scan` 统计命中条数，
切不出节时退化为整段扫描。

### v11 实测
```
[patch] 生成 8 个补丁，应用 8 个（跳过 0，其中改坏 0）
[stage] 复评 62.0 分未涨，但确定性缺陷 10→5 条，保留本轮改动继续
        （不因判官抖动回滚已改好的稿子）
```
这条分支在 v11 里真的救回了一轮——按旧逻辑它会被整轮回滚。

## 三、判官判断标准

### 根因（三条，都来自 v9/v10 判词）
1. **判官自创标准**：「节长失衡」在 800 与 1100 字并存时判 high；
   「人物自省宣言」判成「总结升华段」；「句子别扭」判成「AI 腔」。
   写手照着改，永远改不到点子上——因为清单里根本没这一条。
2. **high 数与分数打架**：v11 里 high 从 4 涨到 6，分数却从 58 涨到 68。
   同一个稿子两个指标背向走，说明判官在不同维度上用的是不同尺子。
3. **同一条问题拆成几条报**（重复、逻辑、时间线其实是同一个场景重复消耗）。

### 改法：`prompts/review.md` 新增「判据定义与豁免（硬口径）」
- 通用三条：① **只按清单判**，清单外的不许判 high；② 每条 issue 的 `note` 必须嵌
  一小段（≥8 字）能从正文**逐字找到**的原文，找不到就是不报；
  ③ 同一处问题只报一条。
- 逐维度给量化门槛与豁免口径：
  - 重演/时间线倒退：同一场戏同一动作同一条信息从头再来才算；
    **豁免**——上一节停在半途、这一节顺势写完是正常承接（判信息是否被重复消耗）。
  - 场景重复：换了地点/对手/信息就不算，哪怕都叫「赐汤」。
  - 节长失衡：只在「最长÷最短 > 2.0」或「单节 > 1500 字」判 high。
  - AI 腔：只认清单点名词形及其同构变体（嘴角勾起一抹 / 眼底闪过一丝 / 就在这时 /
    空气凝固 / 不由得 / 不禁 / 一丝·一抹·一股）。
  - 升华段：故事结束后讲道理才算；故事内人物自省、宣言不算。
  - 逻辑/现实：只有读者会当场出戏的矛盾（凭空出现/死人复活/时间对不上/
    知道不该知道的事）判 high；推演层面不够合理判 mid。

### 顺带修掉的另一处「判据打架」
体检工具 `studio/audit.py` 判「A结构/导语」失败，流水线自己的 `submission()` 判 B 可投
**同一篇稿子**。根因：体检取**固定前 6 行**找「导语」，而成稿版式是
标题 / 空行 / 平台行 / 空行 / 一句话故事 / 空行 / `**导语**：…` —— 导语恰好第 7 行。
改为「第一个节头之前的全部内容」。

## 四、v11 真跑结果

| 指标 | v10 | v11 |
|---|---|---|
| 字数 | 10023 | 9144（体检口径 9509） |
| 主编评分 | 6.3 | **6.8** |
| 交付等级 | B 可投 | B 可投 |
| 失败项 | A结构/导语（误判） | 无（修完体检后） |
| 终审修复轮数 | 7 轮 / 无上界 | 7 轮 / 上界 20 + 守卫终止 |
| 确定性缺陷（终稿） | — | 10 → 5 条 |

体检（`tools/manuscript_audit.py`）：缺陷总分 0.74/千字、碎句 0、长句 0、
碎句链 0.42/千字、语序 0、欧化 0、冗余 0、跨章重复 0、对话占比 25.2%、节长极差 1.59×。
**语言维度全部达标**；仍是 B 级，卡在「主编评分 6.8 < 7.0」。

判官给出的 high 硬伤集中在**写作侧**：小节 03/04 与 06/07 的时间线倒退、
银针/运劲改脉这类前文没交代的手段凭空出现、同一动作在一节内写两遍。
这些不是判据问题，是逐节写的衔接契约还不够硬——下一轮该动的方向。
