## 二、事故复盘：99 617 字失控成稿（本轮最重要的发现）

项目 `workspace/projects/20261025_211149_…` 的成稿是 91 万字符 / 99 617 字，目标 8000–12000。取证复算与 `report.json` 三项字段逐字吻合，确认是代码缺陷链而非模型偶发：

| 环 | 缺陷 | 机制 | 本轮修复 |
|---|---|---|---|
| A（上游） | `llm.py` 把思考型模型的 `reasoning` 无条件当正文回退 | glm-5.3 把 16384 输出预算全烧在英文思维链上，`content` 为空 → 思维链被当正文落盘 8 章共 19.4 万字 | `_reasoning_is_cot()`：计划式英文标记 ≥2 / 英文多于汉字 / 提纲行 >40% 判为思维链，直接抛 `LLM_EMPTY` 让上层重试，不再当正文 |
| B（漏检） | `_english_think_leak` 只看首 400 字且要求"中文 <10" | 思维链里夹了中文 beat 摘要 → 判为非泄漏 → 整份落盘并当 `history` 喂给下一章 | `langqa.think_leak()` 改**全文**口径（思考标志行/英文行占比/提纲行三指标），并接入写稿门禁：命中即带提示重写一次，仍命中记 `maxed_thinkleak` |
| C（放大器1） | `_split_full_sections` 用前缀匹配 `^\d{1,2}` 认节头 | 正文里「24 岁那年…」「45个人围着我」被当成节头 → 全稿切成 **393 个碎片节** | `SEC_HEAD` 改整行严格匹配（≤26 字符、无句末标点、含汉字、非英文、编号后不接数字）；`MAX_SECTIONS=60` 上限，超限判定识别失效并退回整稿模式 |
| C（放大器2） | `_rewrite_section` 按 `no` 回写**所有**同号节 | 393 个碎片节里编号重复极多，一次扩写把新文本刷进几十个节 → 字数指数膨胀 | 改为**就地改目标 dict**（3 处同型 bug 一并修：字数门、密度去味、`_pad_words`） |
| C（放大器3） | 压缩死锁：`tgt = max(now-(total-ceil)-200, 600)`，而守卫要求 `new_w ≥ now*0.4` | 单节 18992 字时目标 600 < 守卫下限 7597 → **8+8 轮全部被拒**，`total` 恒 193851；`writer.calls=24` 里 16 次是空转，约 2/3 写手预算烧掉 | 目标与守卫同源（`max(..., now*0.55)`）；超标 >1.2× 走**整稿压缩兜底**；连续 2 轮字数变化 <300 判空转终止；>1.5× 失控上限直接停手 |
| D（销毁） | `_final_clean` 把"数字开头的行"整行替换成裸编号 | 435 行被吃掉，**销毁 94 234 字（48.6%）**，193851 − 94234 = 99617（与 `final_words` 误差 0） | 只改**真节头**：按"期望编号 prev+1"判定，跳号/重复顺延，编号远超本篇节数的判为正文原样保留；`word_flow` 落盘前后字数差 |
| E（治理） | 淘汰只判字数下限 | 99 617 字 `platform_check.pass=true` 留在工作台；`maxed_words_high` 无淘汰路径 | 淘汰策略覆盖下限/上限/字数门打满三路；`platform_check` 增加 `max_words` 判定 |

修复后本地复算（不调 LLM）：失控稿 `_split_full_sections` 返回 `[]`（守卫拒绝逐节处理，告警可见），`_final_clean` 节头序列严格单调、正文不再被吞；正常项目（8–9 千字）清理前后偏差 ≤3.8%，与修复前一致。

## 八、结论：还剩什么

按用户要求"逐项测试 + 检查联动 + 借鉴 openwrite"，本轮把**能确定性验证的部分全部转绿**。仍未闭环的按优先级登记：

3. 润色授权边界：patch 新增人名/实体、总量 <0.9× 一律拒收（治"越修越短"）。
