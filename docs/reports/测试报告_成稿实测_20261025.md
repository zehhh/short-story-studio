### 1.1 最终配置（写手之外全部 deepseek-v4.1-flash）

### 1.2 403 的真正原因（不是欠费、不是 key 失效）

原始响应体（写手通道）：

```json
HTTP 403
{"error":{"message":"Free quota exhausted. To continue accessing the model on a paid basis,
 please add funds or disable the \"use free tier only\" mode in the management console.",
 "type":"insufficient_quota"}}
```

同工作区交叉验证，证明是**账号模式**而非配额：

| 模型                                                                                  | 结果                                 |
| ----------------------------------------------------------------------------------- | ---------------------------------- |
| qwen3.8-flash / qwen-flash / qwen-plus / qwen3.8-max                                | 403 `AllocationQuota.FreeTierOnly` |
| **kimi-k3**、**glm-5.3**、**qwen3.8-27b**、**qwen3.8-max-0902**、**qwen3.8-omni-flash** | **200 OK**                         |

即：该百炼工作区被设为「仅使用免费额度 / 免费额度用完即停」，只有免费额度内的模型可用；关闭该模式后 `qwen3.8-flash` 立即恢复 200。

### 1.3 处置

1. 用户关闭控制台「用完即停」→ 复测 `qwen3.8-flash` = 200；
2. `config.yaml` 写手段落恢复阿里云原生通道（含 `extra_body.enable_thinking: false`），并在注释里写清**两种自救方式**（关控制台开关 / 临时切 opencode 通道，模型名不变）；
3. 已确认同一模型在 opencode 网关也可用（备用通道实测 1.7s 出稿），故障时可零改提示词切换。

## 六、建议（按优先级）

**配置层（立刻可做，零代码）**

1. 按模型标定阈值：deepseek-v4.1-flash 主编分明显偏严（3.5–5.5），把 `score_threshold` 降到 6.5–6.8 或改用双模型投票；否则"0/8 通过"会成为常态，门禁失去区分度。
2. `max_reader_rounds: 1` → 2 或 3（当前"读者门从不重写"）；若坚持省 token，就把该门改名为 `score_only` 并**不要计入打满**（语义诚实）。
3. `stage_gate_rounds: 2 → 3` 且大纲要求"逐节输出"（planner 一次吐 8 节 JSON 易截断）。

**代码层（下一批）**  
4\. 大纲分节生成：改成"先出 8 行目录 → 逐节补 beats/ends"，从根上消掉截断（对应 F3）。  
5\. `numfix` 增加"总量复述"识别（同一金额/年限出现 ≥3 次即报），否则该修复器对账本型题材无效（F4）。  
6\. 末节收束硬检：末节出现"新威胁/新危机"句式（"你以为…""才刚开始""还有一拨人"）即打回重写（对应 C2，`polish_ending` 已有提示词，缺确定性检测）。  
7\. 节长约束：写章阶段对单节上限做确定性截断/告警（当前 1 838 字 vs 目标 1 125，超 63%）。  
8\. `project.json`/`report.json` 落 `mode` 字段（F8）。

**内容层（提示词）**  
9\. 导语与首节"不重演"约束：导语只给"最高潮一句 + 悬念"，01 必须从**下一拍**开始（C1）。  
10\. 账目复述限量：同一金额/年限全文 ≤2 次，第 3 次必须换成"结果/后果"表述（C3）。
