## 0. 一句话结论

**四类语言病之所以"修了还在"，根因不是提示词不够狠，而是语言打磨这条链路从上线起就整体抛异常、被 `except Exception` 吞掉，等于从未运行过。**
本轮定位并修复该 P0，随后用真实模型实测：同一篇稿子缺陷分 **127 → 61（-52%）**，碎句 **33 → 12**，冗余 **88 → 44**。

## 1. P0：语言打磨从未生效（本轮最重要的发现）

### 1.1 现场

`studio/language.py:polish()` 小节改写后有一句越界保护：

```python
if len(_count_sec_heads(new_text)) > 1:      # ← _count_sec_heads 返回 int
```

`_count_sec_heads()` 的签名是 `-> int`，`len(int)` 必抛 `TypeError`。
而调用点 `studio/pipeline.py`（stage_polish）是这样兜的：

```python
except Exception as e:
    print(f"[lang] 语言打磨跳过（{type(e).__name__}: {e}），继续体检")
```

于是：

1. 每一节改写成功后，**在写回之前**崩溃；
2. 整轮打磨抛异常 → 被兜住 → 打印一行就继续；
3. 成稿照样进体检、照样评分、照样入库；
4. `report.json` 里 `lang_polish` 甚至没有字段（走的是 `{"enabled": False}` 分支），
   复盘时看不出"语言打磨根本没跑"。

**这就是"改了提示词、加了规则，成稿还是那四类病"的真正原因。**

### 1.2 修法

| # | 位置 | 改动 |
|---|---|---|
| 1 | `studio/language.py` | `len(_count_sec_heads(...)) > 1` → `_count_sec_heads(...) > 1` |
| 2 | `studio/pipeline.py` | 异常不再静默：`_lang_err` 记下 `TypeError: ...`，日志打 `⚠` 警告"成稿可能带四类语言病" |
| 3 | `studio/pipeline.py` | `report["lang_polish"] = {"enabled": True, "pass": False, "error": ...}`，让看板/复盘/淘汰能看出"开了但没跑成" |

> 教训（写进 `docs/dev/DECISIONS.md`）：**`except Exception: print(...)` 是静默失败工厂**。
> 只要是为了"不阻断主流程"而吞异常，就必须同时把失败写进 `report`，否则下游会把
> "没做"当成"做完且通过"。本项目已出现过两次同型事故（本次 + 早期 `reviews/chNN.json` 不落盘）。

### 1.3 为什么测试没抓到

原测试 `test_lang_polish_wired_and_guarded` 只断言**源码里有** `CRAFT=` 字样、模板里有 `{{CRAFT}}` 占位符 —— 接线齐全，逻辑全错，照样绿灯。

新增 `tests/test_lang_polish_behaviour.py`（**行为断言**）：

- 喂一段四病混排的真文本 + 桩写手，断言"模型真被调用""至少一节改写成功""缺陷分真下降""小节头没丢"；
- 第二个用例断言"模型返回多个小节头 → 整节拒收，不污染成稿"；
- 该文件既能 `python -m pytest` 跑，也能 `python tests/test_lang_polish_behaviour.py` 直接跑；
- 已登记为 `python -m studio verify` 的**第 8 项检查**（`语言打磨行为`），不依赖 pytest 是否安装。

## 2. 修复后的实测（真实模型）

对被判最差的一篇历史成稿（9007 字）跑独立语言打磨：

```bash
python tools/lang_polish_live.py "workspace/projects/20261009_123056_彩礼六万八..." --rounds=2
```

| 指标 | 改前 | 改后 | 变化 |
|---|---|---|---|
| 缺陷总分 | **127** | **61** | **-52%** |
| 碎句 frag | 33 | 12 | -64% |
| 冗余 redundancy | 88 | 44 | -50% |
| 欧化 euro | 3 | 2 | -33% |
| 详略 detail | 3 | 3 | 持平 |
| 字数 | 9007 | 8459 | -6.1%（在 ±12% 授权内） |
| 改写小节 | — | 6 节 | 拒收 2 节 |

拒收的 2 节都是**守卫正常生效**：一节模型多写了小节头（越界），一节缺陷分 30→30 未下降（≥30% 降幅门槛）。

### 2.1 改动质量（人工复核，非只看分数）

小节 01 实例：

| 改前 | 改后 | 病种 |
|---|---|---|
| 只是**慢条斯理地**抽出纸巾 | 只是抽出纸巾 | 冗余·口癖 |
| 我**瞥见他嘴角一丝不易察觉的**抽动 | 他嘴角抽动了一下 | 欧化·长定语前移 |
| 心里那本账瞬间翻到了三年前**：** | 心里那本账瞬间翻到了三年前**。** | 冗余·冒号套嵌 |

方向正确：删的是"AI 修辞"，不是删情节。

### 2.2 顺带修掉的调参缺陷

- `MAX_SECTIONS_PER_ROUND = 4` 写死 → 12 节的中短篇 3 轮才轮完一遍，而默认只给 2 轮，**后半篇永远排不上**。改为 `max(4, ceil(小节数/2))`。
- `lang_polish_rounds` 默认 2 → **3**（实测第 2 轮仍有明显下降空间）。

## 3. 知识库：系统侧 + 内容侧

### 3.1 系统侧（已修）

| 缺陷 | 影响 | 修法 |
|---|---|---|
| `hooks`（开头钩子）/ `cases`（同类爆款案例）**从未进过任何提示词** | 42 张卡花 token 蒸馏出来的两类资产全废 | `digest()` 纳入这两个分区 |
| `digest()` 按"条目长度"截断预算 | 钩子/案例最长 → **整类被挤掉** | 无查询词时改为**按分区轮流各取一条**（round-robin），保证 8 个分区都在 |
| 每章注入**同一份**摘要 | 8 章反复吃同一批 facts → 直接助长"同一信息写三遍" | `digest_for(query=章节文本, exclude=已用key)`：按章检索 + 跨章去重，`report` 落 `kb_used.json` 可在看板查看 |
| `cases` 键名只认 `title/takeaway` | 人工补写的 `pattern/beat/why` 被当成空 | 键名容错（title/name/pattern/tag × takeaway/why/beat/note） |
| `load_card()` 每节重读十几 KB JSON | 语言打磨按节取卡 → 每节一次磁盘解析 | mtime 缓存，`kb collect` 重写后自动失效 |
