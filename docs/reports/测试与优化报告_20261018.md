## 三、知识库系统专项

调用链：`写入`（拆书/素材沉淀/知识卡 → `units.jsonl` + `vectors.npy` + PPMI 共现）→ `检索`（BM25[字符 bigram] ‖ 向量 KNN ‖ 共现扩散，RRF 融合 + 弧位定向加权）→ `注入`（逐章 draft / 导语模式库 / 大纲结构骨架）。

实测：
- `kb stats`：161 267 单元 / 向量已索引 161 267 / 共现节点 5 073，按弧位/类型/题材分布正常。
- `kb recall --q "离婚 净身出户 后悔 追妻" --arc 转`：命中 12 条，含 `technique/quote/hook/arc_segment` 混合类型，弧位定向生效。
- 生成过程注入：方案 371 字、圣经 362 字、逐章 476–516 字（每章 7–12 条），均按「核心梗 + 方向 + 弧位」检索。
- 降级路径：断网时知识卡走 LLM 内化并标注「未联网核实」（冒烟测试覆盖）。

规模数据：`units.jsonl` 90 MB / `vectors.npy` 2.6 GB → 优化后检索用 330 MB，写作期每次检索约 1.7 s，不再成为瓶颈。

## 六、剩余风险与下一步

1. **长任务受会话边界影响**：本环境下后台进程会在对话轮次结束被回收，长生产应单轮跑完或用 `continue` 分阶段续跑（项目状态已支持）。
2. **GLM-5.3 限制**：思考型模型，`reasoning_effort/thinking` 关闭会 400；`temperature` 亦被忽略，调 `max_tokens ≥ 32768` 才稳。
3. **阈值需按模型标定**：`stage_gate_threshold`（现 7.0）、`score_threshold`/`final_score_floor` 与换用的评审模型强相关，换模型后应先用 3–5 篇做标定。
4. **未覆盖链路**：`deconstruct`（真 LLM 拆书）、`fetch`（笔趣阁/起点/onehu 抓取）、`scheduler` 常驻、`fanqie_draft`（Playwright）、`kb migrate/rebuild`（16 万级耗时）——建议接入 CI 小样本回归。
5. **知识库体积**：`units.jsonl` 已 90 MB、向量源文件 2.6 GB，建议定期 `kb dedup`（已有语义阈值 0.93）并归档冷单元。
