## 1. 用户四类问题 → 判据 / 修复 / 门禁 全链路

| 用户抱怨 | 确定性判据（`studio/language.py`） | 零 token 修复 | 模型返修 | 门禁 |
|---|---|---|---|---|
| 一句话拆成几个短句 | `_local_frag`（≤9 字碎片连排） | `merge_chain_sentences` | `defect_brief` 定点重写 | 章级 `maxed_langdefect` + 整稿 `market_lang` |
| 同类短句连排成链 | `_local_chain`（≤22 字同主语连排 ≥3 句） | 同上（同一判据 `_chain_member`） | 同上 | 同上 |
| 句子不符合中文语序 | `_local_order`（数量词后置 `一AA一`、`名词+数量`倒装） | — | 同上 | 同上 |

（有单测 `test_market_target_single_source` 守着，不许再写死数字）。

## 2. 本轮修掉的真实缺陷（每条都有实测证据）

| # | 缺陷 | 证据 | 修法 |

| 4 | 对话句被 `！` 截断 → 台词被算碎句 | e2e7 `frag 0.49`，唯一命中项是 5 句台词 | `sents_with_dialog()` 按引号深度判（决策 10） |

## 5. 验收标准（成稿级）

一篇成稿算「符合短篇网文市场评价标准」需同时满足：

1. 字数 8000–12000（投稿口径含标题+导语）
2. 节数 5–12，节长极差 ≤2.0×
3. 缺陷密度：`chain/frag/order/euro/redundancy/detail` 全部 ≤ `MARKET_TARGET` 对应线
4. 对话段占比 ≥0.25
5. 无 `“ ”` 残留、无思维链、节头严格递增、无 high 级 AI 味
6. 主编评分（评分卡折算）≥7.0，读者团全 ≥7.5
7. `platform_check.pass == true`

`python tools/manuscript_audit.py <项目目录>` 一条命令给出 A/B/C 与失败项，
与流水线的 `report["audit"]`、`report["submission"]` **同一函数**计算（不分裂）。

## 7. 遗留（未做 / 建议）

1. **对话占比的根治**：门禁只能把章节拉到线上，真正的杠杆在大纲阶段
   （每节标注「当面对峙/电话/独处」），下一步应把「场面类型」写进 `outline.json` schema。
2. **详略是语义判断**：现有判据只能抓「超长无对话段 + 事件密度」两种硬伤；
   真正的「该详写略了」需要章组级审计（B18），未做。
3. **欧化句**规则仍偏保守（只有 6 条），长定语套叠、被动式滥用还没覆盖。
4. `pipeline.py`(200KB+) 与 `dashboard.py`(130KB) 需要拆分，否则单人维护成本会持续上升。
5. 知识库 `cases`（同类爆款案例）字段在无外网环境下无法补充真实数据，目前只保留人工整理的少量条目。

## 8. 复现方式

```bash
# 1. 全量守卫
python -m studio verify

# 2. 知识库体检
python -m studio kb lint

# 3. 单篇生产
python -m studio run --idea "<一句话选题>" --mode agent --words 9000

# 4. 成稿体检（A/B/C + 失败项）
python tools/manuscript_audit.py workspace/projects/<项目目录>

# 5. 零 token 返修（对已有成稿，不调 LLM）
python tools/manuscript_audit.py <项目目录> --heal
```
